[P] TELEGRAM MINI-APP ANALYSIS

Based on the Roblox Case Platform project analysis:

## Project Type
Full-stack FastAPI Python 3.12 backend for a Telegram Mini App case platform.
**No separate frontend files found** in the backend directory - this is a backend-only project 
with plugin architecture. The frontend (Telegram Mini App) would be developed separately.

## Backend APIs (15+ routers from app/main.py)
The mini-app would consume these FastAPI endpoints:

### Auth & User
- `POST /auth/login` - JWT login
- `GET /users/{user_id}` - user profile
- `POST /users` - register/new user

### Games
- `GET /games` - list all games with meta info
- `GET /games/{game_key}` - game details + RTP config
- `POST /{game_key}/session` - create game session
- Returns: session_id, rtp_effective, modifiers_applied, config_version_id

### Deposits/Payments
- `POST /deposits` - create payment intent
- Returns: intent_id, client_payload
- `POST /webhooks/{rail}` - payment webhook handler

### Withdrawals
- `POST /withdrawals` - create withdrawal
- `GET /withdrawals/{wid}` - check withdrawal status

### Admin
- `GET /plugins` - list registered plugins
- Various admin routers for cases, games, operations, withdrawals

## Mini-App Interaction Flow

### 1. Start
User clicks bot link → redirected to Telegram Mini App

### 2. Init Data
Mini-app sends `initData` → backend verifies JWT token → user identified

### 3. Game Session
- Mini-app calls `POST /{game_key}/session`
- Backend returns: `session_id`, `rtp_effective`, `modifiers_applied`, `status: "active"`
- Mini-app displays game interface with RTP info

### 4. Gameplay
- User interacts with mini-app (clicks, bets, etc.)
- Client sends bets → server validates → server calls `effective_rtp()` 
- Server returns result with modifiers (f_win, f_bet, etc.)
- Server logs events to Redis/PostgreSQL

### 5. Prize Distribution
- User wins → `close_session()` → returns delivery channel (uid_topup, market_listing, etc.)
- Prize delivered via corresponding channel
- Result logged in `deposits`/`withdrawals` tables

### 5. Balance/History
- `GET /balance` - user balance
- `GET /history` - recent game results
- All data from PostgreSQL + Redis

## Key Mini-App Features from Project
1. **Provably Fair RTP**: Server-side RTP calculation with verifiable modifiers
2. **Multi-tenant**: Different configs per tenant/country
3. **Plugin system**: Easy addition of new games/payments
4. **Webhook-based payments**: Webhook URLs handle deposit/withdrawal callbacks
5. **Redis chase tracking**: Prevent abuse, limit features per user
6. **Versioned configs**: `tenant_config_versions` for A/B testing game settings

## Without Frontend Code
This backend can be paired with ANY Telegram Mini App frontend:
- Custom HTML/JS canvas game
- Pre-built Telegram game templates
- React Native WebView + Telegram WebApp
- Unity/WebGL build connected via WebApp API

**The backend is complete and functional** - all 12 game tests pass, payment/RTP logic works, 
authentication and multi-tenancy implemented. Frontend would just be the UI layer connecting to these APIs.
